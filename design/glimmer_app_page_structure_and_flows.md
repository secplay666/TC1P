# 微光 App 页面结构与核心用户流程

## 1. 产品定位

微光 Glimmer 是面向陌生人社交的近距离通讯 App。手机 App 连接用户自己的 Glimmer 终端，终端之间通过 BLE 扩展广播进行邻近发现和 P2P 消息传输。App 不强调“蓝牙设备调试”，而强调“附近有人发来一束微光”。

设计目标：

- 让用户知道附近有谁，但不过度暴露精确距离和身份。
- 让第一次开口足够轻，不像正式加好友那么重。
- 让离线、距离过远、发送失败等状态被清楚表达。
- 让连接终端这件事尽量安静，只在异常时提醒。
- 保留开发期诊断入口，但不出现在普通用户主路径里。

## 2. 信息架构

```text
启动
  -> 权限与终端连接
  -> 主界面

主界面
  -> 附近
       -> 附近微光列表
       -> 陌生人简短资料
       -> 发出问候
       -> 进入聊天
  -> 消息
       -> 会话列表
       -> 聊天详情
       -> 发送失败/重试/撤回本地草稿
  -> 我的
       -> 昵称、头像、简介
       -> 可见性状态
       -> 我的 Glimmer 终端
  -> 安全
       -> 隐身模式
       -> 可被发现范围
       -> 屏蔽与举报
       -> 数据保留策略
```

## 3. 页面结构

### 3.1 启动与权限页

用途：

- 解释为什么需要蓝牙和位置权限。
- 引导用户连接自己的 Glimmer 终端。
- 避免一上来出现工程化术语。

关键内容：

- App 名称：微光 Glimmer。
- 状态文案：正在寻找你的 Glimmer。
- 权限说明：
  - 蓝牙：用于发现和连接你的 Glimmer。
  - 位置：Android 扫描 BLE 所需系统权限，不记录 GPS 轨迹。
  - 通知：用于提示收到新的微光消息。
- 主按钮：开始连接。
- 次按钮：稍后再说。

状态：

- 未授权。
- 正在扫描终端。
- 已连接终端。
- 找不到终端。
- 终端电量低。

### 3.2 附近页

用途：

- 展示周围可见的微光用户。
- 让用户感受到“附近有人”，但不显示精确坐标。

布局：

- 顶部连接状态条：我的 Glimmer 已连接 / 信号良好 / 电量。
- 中部“微光场”：用点位、强弱和简短标签表达附近状态。
- 下方附近列表：
  - 昵称。
  - 一句话介绍。
  - 信号等级 S1/S2/S3。
  - 最近活跃状态。
  - 是否已打过招呼。

主要操作：

- 扫描附近。
- 查看对方资料。
- 发出问候。
- 进入聊天。

空状态：

- 附近暂时没有微光。
- 终端未连接。
- 隐身模式已开启。

### 3.3 陌生人资料预览

用途：

- 在聊天前给用户一个轻量判断。
- 不展示真实身份，只展示对方主动公开的内容。

内容：

- 昵称。
- 气质标签。
- 一句话。
- 最近一次被发现时间。
- 信号等级。
- 共同状态，例如“刚刚与你擦肩而过”。

操作：

- 发送问候。
- 直接聊天。
- 暂不显示此人。
- 举报或屏蔽。

### 3.4 消息列表页

用途：

- 管理已发生的微光会话。

内容：

- 会话头像/昵称。
- 最后一条消息。
- 发送状态：
  - 已送达。
  - 等待终端发送。
  - 对方暂不可达。
  - 发送失败。
- 未读数。

筛选：

- 全部。
- 附近。
- 未读。
- 发送失败。

### 3.5 聊天页

用途：

- 完成真正的陌生人沟通。

顶部：

- 对方昵称。
- 近距离状态：附近 / 刚离开 / 暂不可达。
- 终端连接状态。

消息区：

- 自己发送的消息。
- 对方消息。
- 系统状态消息：
  - 对方已进入可达范围。
  - 对方暂不可达，消息未送达。
  - 你的 Glimmer 已断开。

输入区：

- 文本输入。
- 发送按钮。
- 发送失败后提供重试。

发送状态映射：

```text
App 点击发送
  -> 终端接受队列：发送中
  -> P2P ACK 成功：已送达
  -> P2P 超时失败：未送达
  -> 终端断开：未发送
```

### 3.6 我的页

用途：

- 设置自己在附近被看到的样子。

内容：

- 昵称。
- 头像。
- 一句话介绍。
- 兴趣标签。
- 可见性：
  - 正常可见。
  - 只接收不展示。
  - 隐身。
- 我的 Glimmer：
  - 连接状态。
  - 电量。
  - 固件版本。
  - 重新连接。

### 3.7 安全页

用途：

- 陌生人社交必须让用户随时有退路。

内容：

- 隐身模式。
- 不接收陌生问候。
- 只允许附近强信号用户发消息。
- 屏蔽列表。
- 举报入口。
- 本地消息保留时间。

默认策略：

- 新用户默认可被发现，但资料内容很少。
- 默认不展示精确距离。
- 默认不做离线消息，发送失败要明确反馈。

### 3.8 设备诊断页

用途：

- 开发和内测使用。
- 不放在底部主导航里，从“我的 Glimmer”连续点击版本号进入。

内容：

- GATT 连接状态。
- 本机 short id。
- peer 表。
- P2P 统计。
- 最近错误。
- shell 命令入口。

## 4. 核心用户流程

### 4.1 首次使用

```text
打开 App
  -> 看到微光介绍
  -> 授权蓝牙/位置/通知
  -> 扫描自己的 Glimmer 终端
  -> 连接成功
  -> 设置昵称和一句话
  -> 进入附近页
```

成功标准：

- 用户知道权限用途。
- 用户知道自己已经连接终端。
- 用户能在 30 秒内看到附近页。

### 4.2 发现附近的人并发起聊天

```text
附近页显示可见微光
  -> 用户点击某个人
  -> 查看资料预览
  -> 发送问候
  -> 对方收到问候
  -> 双方进入聊天
```

设计重点：

- 第一次互动要轻，避免“申请好友”的压力。
- 对方没有回应前，减少强打扰。

### 4.3 两台手机通过两块 Glimmer 互聊

```text
手机 A 连接 Glimmer A
手机 B 连接 Glimmer B
Glimmer A 与 Glimmer B 互相发现
手机 A 发送消息
  -> Glimmer A 排队
  -> P2P 广播分片发送
  -> Glimmer B 重组与 ACK
  -> 手机 B 收到消息
手机 B 反向同理
```

用户可见状态：

- 发送中。
- 已送达。
- 对方暂不可达。
- 发送失败。

### 4.4 对方离开范围

```text
用户发送消息
  -> 本机 Glimmer 尝试 P2P 发送
  -> 超时没有收到 ACK
  -> App 显示未送达
  -> 用户可选择重试或删除
```

设计原则：

- 不做长期离线消息。
- 不让用户误以为消息已经送达。
- 失败状态要比技术日志更直白。

### 4.5 用户想暂时不被看到

```text
进入安全页
  -> 打开隐身模式
  -> 附近页切换为空状态
  -> App 提示仍可连接自己的 Glimmer
  -> 关闭隐身后恢复可见
```

## 5. MVP 范围

第一版正式 App 建议只做：

- 连接自己的 Glimmer。
- 附近用户列表。
- 基础资料。
- 一对一聊天。
- 发送状态和失败反馈。
- 隐身模式。
- 屏蔽用户。
- 设备诊断隐藏页。

暂不做：

- 账号体系。
- 云端消息同步。
- 离线消息。
- 群聊。
- 复杂推荐算法。
- 真实地理地图。
