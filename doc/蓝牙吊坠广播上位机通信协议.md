# 蓝牙吊坠广播上位机通信协议

## 1. 背景

Telink B85m Single Connection SDK 当前未提供连接态扩展广播共存能力。为了避免“连接上位机后只能使用 31 字节 legacy 广播”的限制，上位机通信改为无连接模式：

- 设备不再依赖 GATT 调试服务。
- 设备持续使用 Extended Advertising 发送状态、响应、日志和事件。
- 设备持续扫描 Extended Advertising，接收上位机命令和其他吊坠帧。
- 上位机也作为一个广播节点，扫描吊坠 Beacon，并通过扩展广播发送命令。

注意：Windows 普通 BLE API / Bleak 通常不能发送自定义扩展广播。PC 工具当前只能提供协议编解码辅助；真正发送端建议优先使用 Android 原生 App、支持原始 HCI 命令的 BLE dongle，或后续专用调试器。

## 2. 总体分层

广播上位机通道复用已有 `PENDANT-ADV` 扩展广播帧：

```text
Extended Advertising Data
  -> Manufacturer Specific Data
    -> PENDANT-ADV frame, Frame Type = Data
      -> HOST-ADV payload
        -> Host Command / Response / Log / Event message
```

固件模块：

| 模块 | 作用 |
| --- | --- |
| `adv_proto` | 负责 PENDANT-ADV 通用扩展广播帧编解码 |
| `adv_scheduler` | 轮询发送 Beacon、响应、日志、事件等广播帧 |
| `scan` | 接收广播报告，分发 Beacon 和 Data 帧 |
| `host_adv` | 通过扩展广播收发上位机消息，负责分片、重组、去重 |
| `host_transport` | 上位机传输统一出口，当前支持 `host_adv`，保留 GATT 兼容 |
| `host_cmd` | 命令业务处理层，复用原有 GET/SET/FACTORY/MOTOR 等命令 |

## 3. HOST-ADV Payload

HOST-ADV Payload 放在 `PENDANT-ADV` 的 Data 帧 Payload 中。

多字节字段均为 little-endian。

| 偏移 | 字段 | 长度 | 说明 |
| ---: | --- | ---: | --- |
| 0 | Magic Lo | 1 | 固定 `0x48`，ASCII `H` |
| 1 | Magic Hi | 1 | 固定 `0x41`，ASCII `A` |
| 2 | Version | 1 | 当前 `0x01` |
| 3 | Type | 1 | `1` Cmd, `2` Rsp, `3` Log, `4` Event |
| 4 | Seq | 1 | 消息序号；响应沿用命令 Seq |
| 5 | Cmd | 1 | 命令或事件 ID |
| 6 | Status | 1 | 响应状态，命令为 0 |
| 7 | Frag Index | 1 | 分片序号，从 0 开始 |
| 8 | Frag Count | 1 | 分片总数 |
| 9 | Total Len | 2 | 完整 Host Message Payload 长度 |
| 11 | Message CRC16 | 2 | 完整 Host Message Payload 的 CRC16 |
| 13 | Chunk Len | 1 | 当前分片数据长度 |
| 14 | Chunk Data | 0-146 | 当前分片数据 |

当前单条 Host Message 最大长度沿用原调试协议：`192` 字节。

## 4. 寻址规则

上位机需要先扫描吊坠 Beacon，取得目标设备的 `Source EID`。

上位机下发命令时：

- `PENDANT-ADV.Source EID`：上位机自身 EID，建议固定 16 字节，例如 `PENDANT-HOST-001`。
- `PENDANT-ADV.Destination EID`：目标吊坠 EID。
- `Frame Type`：`Data`。
- `Data Payload`：HOST-ADV Payload。

吊坠响应时：

- 响应目标为最近一次合法命令的上位机 EID。
- 响应、日志、事件都通过 `host_transport` 发给该上位机。
- 上位机 30 秒无命令后，吊坠认为上位机广播会话过期。

## 5. 可靠性策略

当前第一版为调试可用优先：

- 每个 HOST-ADV 分片重复广播 3 次。
- 接收端按 `Type + Seq + Cmd + TotalLen + MessageCRC16` 做 5 秒去重。
- 尚未实现 ACK、重传请求和发送完成确认。

后续如果要承载正式聊天消息，应继续实现：

- ACK / Partial ACK。
- 缺片重传。
- 消息发送队列状态查询。
- 上位机侧发送窗口和退避机制。

## 6. 当前代码状态

已完成：

- 固件默认切到非连接扩展广播，`APP_BLE_ENABLE_GATT_DEBUG = 0`。
- 固件默认开启扫描，duplicate filter 关闭。
- `host_cmd` 从 GATT 发送出口改为 `host_transport`。
- 新增 `host_adv` 广播上位机通道。
- `adv_scheduler` 从单 pending frame 改为 8 深度队列，并复制 payload。
- 新增 `pc_debug_tool/pendant_adv_protocol.py`，用于上位机侧协议编解码。
- 新增 `pc_adv_probe/` C# + WinRT 最小验证工具，用于验证 Windows 扩展广播扫描和发送能力。

待完成：

- 用 `pc_adv_probe` 实测 Windows 当前蓝牙适配器是否能稳定发送扩展广播 Manufacturer Data。
- 上位机 UI 从“连接 GATT”改为“扫描 Beacon + 投放扩展广播命令”。
- 广播 ACK/重传机制。
- 真实 AES/MIC 安全能力。

## 7. Windows C# WinRT 最小验证工具

工具目录：

```text
pc_adv_probe/
```

当前命令：

```powershell
dotnet run --project pc_adv_probe\PendantAdvProbe.csproj -c Release -- scan 15
dotnet run --project pc_adv_probe\PendantAdvProbe.csproj -c Release -- info
dotnet run --project pc_adv_probe\PendantAdvProbe.csproj -c Release -- info <eid_hex>
dotnet run --project pc_adv_probe\PendantAdvProbe.csproj -c Release -- send <eid_hex> <cmd_hex> [payload_hex]
dotnet run --project pc_adv_probe\PendantAdvProbe.csproj -c Release -- selftest
```

当前本机验证结果：

- `dotnet build` 通过。
- `selftest` 通过。
- `scan 3` 能正常启动 WinRT watcher，未报权限或 API 错误；当时未扫描到吊坠 Beacon。

使用的 WinRT API：

- `BluetoothLEAdvertisementWatcher.AllowExtendedAdvertisements`
- `BluetoothLEAdvertisementPublisher.UseExtendedAdvertisement`
- `BluetoothLEManufacturerData`
