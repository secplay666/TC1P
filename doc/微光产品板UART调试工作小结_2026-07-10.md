# 微光产品板 UART 调试工作小结 - 2026-07-10

## 背景

本次排查的核心问题是：同一块产品板刷老固件可以扫描到 `HHCCHH` 且 COM3 有串口输出；刷当前新固件时，如果尝试打开 PC2/PC3 UART，产品板容易出现扫描不到 `Glimmer` 的现象。

已确认的硬件状态：

- 产品板可以通过 Telink BDT 正常 active、reset、flash。
- 当前串口枚举为 `COM3`，用户已确认老固件在 COM3 有输出。
- 老固件使用的 UART 引脚确实是 `UART_TX_PC2` / `UART_RX_PC3`。
- 当前新固件的产品板安全基线保持 `PENDANT_UART_PINMUX_ENABLE = 0`、`PENDANT_UART_RX_PINMUX_ENABLE = 0`。

## 关键对照结果

### 1. 新固件安全基线

配置：

- 扩展广播开启。
- 扩展扫描开启。
- PC2/PC3 不切到 UART。

结果：

- BDT reset 后可扫描到 `Glimmer`，地址为 `A4:C1:38:9F:98:F1`。
- 该结果说明新固件主体、BLE 扫描工具、产品板 RF 和烧录链路都不是整体不可用。

### 2. TX-only UART pinmux，关闭串口打印和 shell

配置：

- `UART_TX_PC2` 切到 UART。
- RX 不启用。
- 不发送启动日志。
- debug shell 不初始化、不轮询。

结果：

- 20 秒扫描未发现 `Glimmer`。
- COM3 仅抓到零散噪声字节。

结论：

- 问题不是 debug shell 的 RX 轮询导致。
- 问题不是 PC3 RX 浮空噪声导致。
- 问题不是 `u_printf()` 串口发送阻塞导致。

### 3. 延后 UART 初始化

配置：

- 不在 `user_init_normal()` 开头初始化 UART。
- 等 BLE/app 初始化后再做 TX-only UART 初始化。

结果：

- 仍然扫描不到 `Glimmer`。

结论：

- 单纯把 UART 初始化从早期移动到后期，不能规避问题。

### 4. PC2 GPIO 电平对照

配置与结果：

- PC2 作为普通 GPIO 输出低电平：可以扫描到 `Glimmer`。
- PC2 作为普通 GPIO 输出高电平：完整新固件配置下扫描不到 `Glimmer`。

结论：

- 产品板不是“只要碰 PC2 就失败”。
- 更敏感的是 PC2 被拉高，或 UART TX 空闲高电平带来的外部电路状态。

### 5. BLE 工作模式对照

配置与结果：

- PC2 高电平 + legacy BLE：可以扫描到 `Glimmer`。
- PC2 高电平 + 扩展广播开启 + 扫描关闭：扫描不到 `Glimmer`。

结论：

- PC2 高电平不是单独必然导致板子不可见。
- 当前触发条件更接近：产品板 PC2 高电平 / UART TX 空闲高电平，与新固件扩展广播路径叠加后导致 BLE 不可见或启动不稳定。

## 当前判断

当前证据不支持“串口线硬件直接影响 BLE RF 发射”这个简单结论。更合理的判断是：

产品板上 PC2 可能不只是普通 UART TX 测试点，或者该网络在高电平时会影响某个外部电路状态。老固件由于使用 legacy BLE、初始化路径和运行负载更轻，所以同样连接串口时仍能广播；新固件启用扩展广播后，该硬件状态被放大成启动/广播异常。

因此当前不建议在产品板上打开：

```c
#define PENDANT_UART_PINMUX_ENABLE 1
```

产品板主线应继续保持：

```c
#define PENDANT_UART_PINMUX_ENABLE    0
#define PENDANT_UART_RX_PINMUX_ENABLE 0
```

## 后续建议

1. 请硬件同事确认 PC2/PC3 除串口测试点外是否还连接到电源控制、马达、充电、唤醒、传感器或其他功能网络。
2. 若产品板必须保留串口调试，优先评估换用不会影响产品功能的 TX/RX 引脚。
3. 若短期必须从产品板输出日志，考虑使用非 UART 外设的极简 trace，例如 analog register、GPIO 低风险翻转，或 BDT/手机 BLE 诊断路径。
4. 后续若继续定位，可做最小工程：只保留扩展广播与 PC2 电平/UART pinmux，逐步加回业务模块，找出最小触发组合。
