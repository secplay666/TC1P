# 微光吊坠间发现扫描与产品板一致性方案（草案，2026-11-01）

## 一、现状

| 项目 | 现状 |
| --- | --- |
| 发现扫描 | `APP_BLE_ENABLE_DISCOVERY_SCAN = 0`，固件里扫描关闭，对端表始终为空 |
| 算法 | RSSI 指数平均（新值权重 1/4）；阈值 T1/T2/T3 = -80/-65/-50 dBm 对应 S1/S2/S3；进入需持续 `tin` = 1.5s，退出需持续 `tout` = 2.5s，每次只升降一级；等级变化时振动并上报手机（0x81 事件） |
| 参数 | 阈值和时间都在配置存储里，调试版可通过 PC 工具的 `SET_RSSI_CONFIG` 修改 |
| 扫描参数 | 被动扫描，间隔 300ms；广播间隔 100ms |
| 未验证 | 阈值来自需求文档的建议值，从未实测；扫描对功耗的影响也未评估 |

## 二、难点

1. 实测时几块产品板要随人移动、改变距离，**不能接串口和 Swire**，调试数据必须通过无线方式拿回来。
2. RSSI 受朝向、人体遮挡、多径影响很大，同一距离可能相差 10 dB 以上。
3. 每块板子的发射功率和接收灵敏度有差异，直接用固定阈值会导致“同样距离、不同板子判定不同”（见第七节）。
4. 扫描会显著增加功耗，并与空闲休眠条件“附近无其他吊坠”耦合。

## 三、调试数据怎么拿回来

推荐组合使用 A + B，C 作为补充。

### A. 广播里带调试信息，旁观者被动记录（推荐，实时）

- 调试版固件在扩展广播（adv1）里追加一个“发现视图”字段：本机看到的前 N 个对端（short_id、平均 RSSI、当前等级），加上本机发射功率档位和序号。
- 一台 PC（或手机）放在测试区域中间，只扫描不连接，持续记录所有吊坠的广播，按时间戳落盘。
- 优点：不需要连接，不影响被测设备的行为；几块板子同时可见；数据实时。
- 限制：旁观者要在所有吊坠的接收范围内（室内 10~20m 一般可以）；广播负载有长度限制，N 取 3~4 即可。
- 工作量：固件在 `app_adv_scheduler` 里加一个调试字段；PC 写一个记录脚本（`raw_scan` 的扩展版）和离线画图脚本。

### B. 板上记录日志，测完用手机或 PC 读回（推荐，完整）

- 固件在 RAM 环形缓冲区记录发现事件：时间、对端 short_id、原始 RSSI、平均 RSSI、等级变化原因。可选每分钟写一次 Flash，防止掉电丢失。
- 新增一条 host 命令 `GET_DISCOVERY_LOG`，分页读取。测试结束后逐块连上读回。
- 优点：数据完整，不受旁观者距离限制。
- 限制：不是实时；RAM 容量有限（例如 200 条 × 8 字节 = 1.6KB）。

### C. 手机随身记录

- 每块吊坠绑定一部手机，App 已能收到等级变化事件（0x81），增加本地日志和导出即可。
- 适合做最终的“用户视角”验收；需要多部手机。

## 四、能否用调发射功率来模拟距离

可以，但只能验证逻辑，不能代替实测标定。

| 方法 | 做法 | 能验证什么 | 不能验证什么 |
| --- | --- | --- | --- |
| **发射功率扫描** | 测试模式下，一块板按时间表循环切换发射功率（B85 可从约 +10 dBm 降到 -20 dBm 以下），当前档位写在广播里；其他板子固定不动 | 等级进入/退出、滞回、`tin`/`tout`、多对端处理、振动和上报。降低 6 dB 约相当于距离增加 1.4~2 倍 | 真实的人体遮挡、朝向、多径 |
| **接收端 RSSI 注入** | 测试模式下给收到的 RSSI 加可编程偏移或预设曲线 | 完全可重复地测试状态机，适合回归测试 | 射频本身 |
| **PC 上跑算法单元测试** | 把 `level_for_rssi` 和进入/退出逻辑抽成纯函数，用录下来的 RSSI 序列在 PC 上回放 | 调参数时快速评估误报、漏报和延迟 | 射频本身 |
| **有线衰减** | 若板子有 IPEX 天线座，用同轴线加可调衰减器连接两块板 | 精确、可重复的 RSSI 对应关系 | 产品板若没有天线座则不可用 |

建议顺序：先用单元测试和 RSSI 注入把算法逻辑做对，再用发射功率扫描在桌面上验证整机行为，最后做真实距离测试。

## 五、实测方案（真实距离）

1. **静态标定**：走廊或空旷房间，两块板相距 0.5 / 1 / 2 / 3 / 5 / 8 / 10 m，每个距离记录 1 分钟，分别测“板子裸放”“挂在胸前（人体遮挡）”“正对 / 背对”。得到距离与 RSSI 的分布，据此定 T1/T2/T3。
2. **动态测试**：一人持板从 10m 走近到 0.5m 再走远，记录等级变化的时间点和位置，评估延迟与抖动；调整 `tin`/`tout` 和平均系数。
3. **多设备**：3~4 块板同时在场，检查对端表容量、广播冲突、扫描占空比对发现速度的影响。
4. **功耗**：扫描开启 / 关闭两种状态下的平均电流（需要电流测量手段），确定扫描占空比，例如每 10 秒扫描 1 秒。
5. **验收**：用手机随身记录（方案 C），按用户场景走一遍。

## 六、需要你决定的问题

1. S1/S2/S3 对应的大致距离目标，例如 S3 ≤ 1m、S2 ≤ 3m、S1 ≤ 10m。
2. 发现的实时性要求：多快算“及时”（影响扫描占空比和功耗）。
3. 扫描是常开，还是只在检测到运动后开启一段时间。
4. 是否需要做发射功率扫描所需的测试模式（固件改动不大）。

## 七、产品板一致性与标定

### 7.1 重要发现：产品板的频偏校准值被覆盖

Telink 芯片在 Flash `0x77000` 保存 24M 晶振的频偏校准值（出厂或产线校准写入），启动时由 `blc_app_loadCustomizedParameters_normal()` 读出并写入晶振负载电容。对比 10 月 31 日的整片备份：

| 板子 | `0x77000` 起始内容 | 含义 |
| --- | --- | --- |
| 开发板 B | `60 ff ff ...` | 已校准，值 0x60 |
| 开发板 A | `ff ff ff ...` | 未校准，使用芯片默认值 |
| 产品板 | `00 00 00 00 00 00 00 3b 02 c0 80 ...` | 被一串应用数据覆盖，校准值读成 0x00 |

SDK 只在该字节等于 0xFF 时跳过校准。0x00 会被当成有效值传给 `rf_update_internal_cap()`，内部负载电容被设成最小值（有效范围 0~0x3F），晶振频率会偏离默认值。

**已验证（2026-11-01 晚）**：0x00 与 0xFF 交替对照，接收条数、RSSI、连接成功率没有可分辨的差别。所以它不是产品板连接问题的主要原因；产品板 RSSI 比开发板稳定低约 10 dB，与电容无关。详见《微光连接超时调查》。

产品板 `0x78000`（SDK 的 SMP 配对信息区）也有同格式的数据，推测是历史上某个固件把自己的数据存到了这两个扇区。当前固件不会写这里：配置存储区放在 `0x76000` 以下（`app_storage_calc_reserved_start()` 会避开 MAC、校准和配对扇区），SMP 也没有启用。

处理情况：

1. 已完成：产品板 `0x77000` 已改为全 0xFF，即芯片默认电容 0x20。原扇区备份在 `artifacts/product_76000_12k_before_capfix.bin`。
2. 正式方案：用频谱仪、BLE 测试仪或参考接收机测频偏，写入正确的校准值。虽然这次影响不大，但量产时仍应标定，频偏过大的板子会更难连接。
3. 固件加保护：在设备信息里上报当前使用的频偏校准值；对 0x00 这类明显异常的值给出告警。

### 7.2 需要标定或统一的项目

| 项目 | 是否需要 | 方法 | 存储 |
| --- | --- | --- | --- |
| 晶振频偏 | 必须 | 产线用仪器或参考机测量后写入 `0x77000` | Telink 校准区 |
| 发射功率 / RSSI 偏差 | 建议 | 屏蔽箱内，与一台“金板”互测：金板收被测板得到 `tx_offset`，被测板收金板得到 `rx_offset` | 工厂记录（已有 `factory` 模块） |
| 电池 ADC | 建议 | 稳压电源两点标定（如 3.6V / 4.2V），存增益和偏移；同时确认产品板的分压比 | 工厂记录 |
| 马达（DRV2625） | 建议 | 上电自动校准一次，保存校准结果（`A_CAL_COMP` 等），避免每次开机重新校准 | 工厂记录 |
| 振动开关 | 不需要标定 | 开关量，由唤醒判定参数统一 | 配置 |
| 32K RC | 不需要 | SDK 运行时自动校准 | — |

RSSI 补偿的用法：`RSSI_修正 = RSSI_原始 - 对端tx_offset - 本机rx_offset`。对端的 `tx_offset` 可以放进广播负载，接收方就能补偿。是否需要做到逐台补偿，取决于实测的板间差异：先用 5~10 块板测一下分布，若差异在 3 dB 以内，可以先不做逐台补偿，只统一阈值。

### 7.3 保持参数一致的做法

- 所有可调参数（阈值、`tin`/`tout`、扫描占空比、空闲时间、发射功率）放在配置存储里，带版本号；固件升级时按版本迁移默认值。
- App 或 PC 工具提供“读取并对比参数”功能，产线和售后可以一键检查。
- 工厂记录里增加标定版本和标定日期，设备信息中上报，方便追溯。
- 产线测试报告记录每块板的标定值，便于统计板间差异、发现异常批次。
