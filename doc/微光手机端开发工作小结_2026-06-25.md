  - EMUI：`EmotionUI_14.2.0`

参与验证的 Glimmer 终端：

- `A4:C1:38:9E:98:82`
  - `short_id=0x140A0B04`
- `A4:C1:38:7C:E7:EA`
  - `short_id=0x120B0100`

### 2.2 鸿蒙手机调试验证

鸿蒙手机可以通过标准 ADB 识别，不需要额外切换到 Harmony 专用调试链路。

已验证：

- 安装 `android_glimmer_probe` 成功。
- BLE 权限可以通过 ADB 授权。
- 能扫描到 `Glimmer`。
- 能连接 Glimmer GATT 调试通道。
- 能正常订阅通知。
- `GET_DEVICE_INFO` 正常返回。
- `GET_PEER_TABLE` 正常返回。

结论：这台鸿蒙手机可以作为后续手机端开发和调试设备。

### 2.3 双手机端到端聊天验证

连接关系：

```text
Pixel 9
  -> Glimmer A4:C1:38:9E:98:82
  -> short_id=0x140A0B04

鸿蒙手机
  -> Glimmer A4:C1:38:7C:E7:EA
  -> short_id=0x120B0100
```

验证结果：

- Pixel -> Glimmer A -> Glimmer B -> 鸿蒙手机：成功。
- 鸿蒙手机 -> Glimmer B -> Glimmer A -> Pixel：成功。
- 两个方向都能收到 `CHAT_TX_OK`。
- 对端手机 App 都能收到 `RX CHAT`。
- 未观察到 GATT 断连、P2P 发送失败、板子卡死或 App 崩溃。

注意事项：

- 使用 ADB `input text` 自动输入英文时，Pixel 中文输入法可能把拼音样式文本转换成中文候选。这是自动化输入方式的问题，不是通信链路问题。
- 后续正式 App 应在消息发送成功后清空输入框，减少重复发送和状态混淆。

## 3. 产品命名与方向

产品名已确定：

- 中文名：微光
- 英文名：Glimmer

产品方向从“蓝牙吊坠调试工具”切换为“面向陌生人社交的近距离通信 App”。

设计原则：

- 不强调蓝牙、GATT、P2P 等工程概念。
- 强调附近、轻量问候、可达状态和安全边界。
- 不展示精确位置。
- 不做长期离线消息。
- 发送失败要明确提示用户，而不是让用户误以为已经送达。
