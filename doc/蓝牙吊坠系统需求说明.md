# 蓝牙吊坠系统需求说明

## 1. 文档目的

本文档用于描述蓝牙吊坠产品的系统级需求，作为后续固件、手机上位机、测试和量产流程设计的依据。

本文档基于以下信息整理：

- 当前项目需求描述。
- `doc/蓝牙吊坠开发板硬件说明.pptx` 中的硬件信息。
- 当前固件工程 `tc_ble_single_sdk/vendor/ble_sample` 的已有实现状态。

本文档中标记为“待确认”的内容表示当前需求尚未完全定版，开发前需要进一步确认。

## 2. 产品概述

蓝牙吊坠产品由一个硬件终端和一个手机上位机组成。

硬件终端基于 Telink TLSR8258/B85 BLE SoC，具备 BLE 通信、设备间广播发现、振动反馈、动作唤醒、电池电压检测、充电检测和本地唯一识别码存储能力。

手机上位机通过 BLE 与单个硬件终端建立连接，用于读取设备状态、接收设备事件、配置参数、发送业务数据，并显示设备发现和通信结果。

多个硬件终端之间通过 BLE 广播互相发现，并通过 RSSI 信号强度判断相对距离等级。终端发现其他终端进入或离开指定距离等级时，应通过振动马达提示用户，并将事件上报给已连接的手机上位机。

多个硬件终端之间还需要通过 BLE 广播实现有限的数据通信。由于 BLE 广播本身不保证可靠送达，系统需要设计一套广播通信协议，用于保证消息完整性、去重、超时和必要的确认机制。

## 3. 系统组成

### 3.1 硬件终端

硬件终端至少包含以下硬件资源：

- MCU：TLSR8258ET32。
- BLE 射频及天线接口。
- 单节锂电池供电。
- Type-C 充电输入，仅用于充电，无 USB 数据通信。
- 电池电压检测电路。
- 充电检测电路。
- 振动检测电路。
- 线性马达。
- 线性马达驱动芯片 DRV2625。
- Telink 单线调试接口。
- UART 调试接口。

### 3.2 手机上位机

手机上位机通过 BLE GATT 与硬件终端通信。

上位机至少需要支持：

- 扫描并连接用户本人的硬件终端。
- 读取设备唯一识别码或其派生标识。
- 读取设备运行状态。
- 接收附近终端发现事件。
- 接收设备间广播通信结果。
- 下发业务消息。
- 配置发现阈值、时间参数、休眠参数等可调参数。
- 读取电池电量和充电状态。
- 读取错误状态。

是否支持 OTA 升级待确认。

### 3.3 设备间通信

设备间不通过 BLE 连接建立点对点链路，而是通过 BLE 广播和扫描实现发现与通信。

设备间通信需要满足：

- 终端周期性广播自身信息。
- 终端持续或周期性扫描其他终端广播。
- 终端根据广播数据识别合法产品。
- 终端根据 RSSI 和持续时间判断发现等级。
- 终端通过广播发送业务消息。
- 接收终端完成消息校验、去重、重组和确认。
- 本机终端将收发结果同步给手机上位机。

## 4. 硬件资源定义

### 4.1 硬件版本说明

旧版硬件：

- 电池电压检测：PB1。
- 振动检测：PA0。
- 马达驱动 I2C SDA：PB6。
- 马达驱动 I2C SCL：PD7。
- 马达驱动触发：PB5。

新版硬件：

- 电池电压检测：PB1。
- 振动检测：PC1。
- 充电检测：PA0。
- 马达驱动 I2C SDA：PB6。
- 马达驱动 I2C SCL：PD7。
- 马达驱动触发：PB5。
- UART RX：PC3。
- UART TX：PC2。
- UART RTS：PC0。
- UART CTS：PC4。

当前需求默认以后续新版硬件为目标版本。

待确认：

- 最终量产硬件是否采用新版硬件。
- 当前开发板是否存在旧版和新版混用。
- 固件是否需要通过编译宏同时兼容两版硬件。

目标引脚分配如下：

| 功能 | 引脚 | 说明 |

| 电池电压 ADC | PB1 | 分压比例为 ADC 电压 = 78.4% 电池电压 |

| 马达 I2C SDA | PB6 | 连接 DRV2625 |
| 马达 I2C SCL | PD7 | 连接 DRV2625 |
| 马达 TRIG | PB5 | 触发线性马达振动 |
| UART RX | PC3 | 调试通信 |
| UART TX | PC2 | 调试通信 |
| UART RTS | PC0 | 调试通信 |
| UART CTS | PC4 | 调试通信 |

当前固件中存在与目标引脚不一致的地方：

- 当前 `main.c` 使用 `GPIO_PD1` 作为深睡唤醒引脚。
- 当前 `app_config.h` 使用 `PB1` 作为 UART debug TX。
- 硬件文档中 `PB1` 是电池电压检测引脚。

后续开发需要先完成引脚定义统一。

## 5. 系统状态定义

### 5.1 状态列表

下位机系统状态包括：

- 初始化状态。
- 广播扫描状态。
- 上位机连接状态。
- 错误状态。
- 休眠状态。

### 5.2 初始化状态

设备上电、复位或从低功耗模式唤醒后进入初始化状态。

初始化状态需要执行：

- MCU 时钟初始化。
- GPIO 初始化。
- BLE 协议栈初始化。
- Flash 参数读取。
- 唯一识别码读取和校验。
- 硬件版本或引脚配置初始化。
- 电池电压检测。
- 充电状态检测。
- 振动检测输入初始化。
- 马达驱动初始化。
- 广播数据初始化。
- 扫描参数初始化。
- GATT 服务初始化。

初始化成功后进入广播扫描状态。

初始化失败后进入错误状态。

### 5.3 广播扫描状态

广播扫描状态是设备的主要工作状态。

进入条件：

- 初始化成功。
- 从休眠状态唤醒且自检成功。
- 上位机连接断开后恢复。

状态行为：

- 周期性广播本终端信息。
- 扫描其他终端广播。
- 维护附近终端状态表。
- 执行 RSSI 发现算法。
- 处理设备间广播消息。
- 接收手机上位机连接请求。
- 启动休眠计时。

退出条件：

- 手机上位机连接成功，进入上位机连接状态。
- 满足休眠条件，进入休眠状态。
- 检测到不可恢复错误，进入错误状态。

### 5.4 上位机连接状态

上位机连接状态表示手机已经通过 BLE 与本设备建立连接。

进入条件：

- 在广播扫描状态下手机连接成功。

状态行为：

- 保持与手机上位机的 GATT 通信。
- 继续广播本终端信息。
- 继续扫描其他终端信息。
- 继续维护附近终端状态表。
- 继续处理设备间广播通信。
- 将设备发现事件上报给手机上位机。
- 将设备间消息收发结果上报给手机上位机。
- 响应手机配置、查询和发送命令。
- 停止广播扫描状态下的普通休眠计时。

退出条件：

- 手机上位机主动断开。
- 设备主动断开。
- 充电开始且策略要求断开。
- 通信空闲超时且策略要求断开。
- 发生不可恢复错误。

退出后默认重新进入广播扫描状态，并重置休眠计时。

待确认：

- TLSR8258 当前 SDK 在连接状态下同时广播和扫描的稳定支持边界。
- 手机连接状态下是否允许进入休眠。
- 手机连接状态下是否允许因充电开始主动断开。

### 5.5 错误状态

错误状态表示设备自检失败或运行中发生不可恢复错误。

进入条件包括：

- 唯一识别码不存在。
- 唯一识别码校验失败。
- Flash 参数区读取失败。
- BLE 初始化失败。
- 马达驱动初始化失败。
- 电池电压过低。
- 充电检测异常。
- 硬件配置与固件配置不匹配。
- 其他不可恢复错误。

状态行为：

- 停止普通业务功能。
- 停止设备间通信功能。
- 周期性广播错误码。
- 如允许手机连接，则向手机提供错误详情。
- 根据错误类型决定是否进入低功耗。

待确认：

- 错误状态是否允许手机连接。
- 哪些错误可恢复，哪些错误不可恢复。
- 错误广播包格式。

### 5.6 休眠状态

休眠状态用于降低功耗。

进入休眠前需要：

- 停止扫描。
- 停止广播。
- 如已连接手机，则先主动断开连接。
- 保存必要运行状态。
- 配置振动检测或充电检测唤醒源。
- 关闭不必要外设。
- 进入芯片低功耗模式。

唤醒后设备重新进入初始化状态，完成自检后进入广播扫描状态。

待确认：

- 使用 deep sleep 还是 deep sleep retention。
- 唤醒后是否需要保留附近终端状态表。
- 马达驱动是否需要重新初始化。

## 6. 状态转换和优先级

### 6.1 基本状态转换

| 当前状态 | 事件 | 下一状态 |
| --- | --- | --- |
| 初始化状态 | 自检成功 | 广播扫描状态 |
| 初始化状态 | 自检失败 | 错误状态 |
| 广播扫描状态 | 手机连接成功 | 上位机连接状态 |
| 广播扫描状态 | 满足休眠条件 | 休眠状态 |
| 广播扫描状态 | 发生不可恢复错误 | 错误状态 |
| 上位机连接状态 | 手机断开 | 广播扫描状态 |
| 上位机连接状态 | 主动断开完成 | 广播扫描状态或休眠状态 |
| 上位机连接状态 | 发生不可恢复错误 | 错误状态 |
| 休眠状态 | 外部动作唤醒 | 初始化状态 |
| 休眠状态 | 充电结束唤醒 | 初始化状态 |
| 错误状态 | 复位 | 初始化状态 |

### 6.2 事件优先级

当多个事件同时发生时，建议优先级如下：

1. 不可恢复错误。
2. 电池严重低压。
3. 充电开始。
4. 手机连接或断开。
5. 设备间消息收发。
6. 附近设备发现状态变化。
7. 普通休眠计时超时。

待确认：

- 充电开始是否一定优先于手机连接。
- 低电压时是否仍允许错误广播。

## 7. 休眠与唤醒需求

### 7.1 休眠条件

满足以下任一条件时，设备应进入休眠流程：

- 无任何外部动作，且范围内无其他互联设备，持续超过指定时间。
- 检测到充电开始。
- 与手机上位机通信无消息持续超过指定时间。

休眠流程应保证：

- 若设备已连接手机，应先通知手机即将休眠，再主动断开连接。
- 若正在发送设备间广播消息，应根据协议策略完成、取消或标记失败。
- 若正在执行马达振动，应根据安全策略停止或等待结束。

待确认：

- “无任何外部动作”的判定标准。
- “范围内无其他互联设备”的判定标准，是否指无 S1/S2/S3 设备。
- 休眠超时时间默认值。
- 手机连接空闲超时时间默认值。
- 充电中是否完全休眠，还是进入充电低功耗状态。

### 7.2 唤醒条件

满足以下任一条件时，设备应从休眠状态唤醒：

- 振动检测电路检测到外部动作。
- 充电结束。

待确认：

- 充电开始是否也需要唤醒后进入充电状态。
- 振动检测需要响应上升沿、下降沿还是双边沿。
- 振动检测是否需要消抖。
- 充电检测是否需要消抖。

## 8. 唯一识别码需求

### 8.1 唯一识别码格式

每个产品需要在内部维护并存储一个 128bit 唯一识别码。

唯一识别码在出厂时预先烧录到 B85 芯片 Flash 内，并在产品生命周期内永久保存。

唯一识别码格式：

| bit 范围 | 字段 | 说明 |
| --- | --- | --- |
| 0-31 | 公司产品序列号 | 固定值 |
| 32-63 | 终端系列号 | 格式 `0xyymmddss` |
| 64-95 | 随机值 | 出厂生成 |
| 96-127 | 保留值 | 固定为 0 |

终端系列号示例：

- 2026 年 3 月 12 日第 5 个产品：`0x26031205`。

### 8.2 存储要求

唯一识别码应存储在 Flash 固定区域。

存储区需要包含：

- 数据版本。
- 唯一识别码。
- 校验字段。
- 写入状态或 magic 字段。
- 保留字段。

设备启动时必须读取并校验唯一识别码。

如果唯一识别码不存在或校验失败，设备应进入错误状态。

待确认：

- 唯一识别码 Flash 地址。
- 是否允许重复烧录。
- 是否需要写保护。
- 是否需要生产工具生成和烧录。

### 8.3 广播标识生成

设备广播时不直接明文广播唯一识别码。

设备应使用 AES-128 对唯一识别码进行加密或派生，生成 128bit 广播 UUID，并将该 UUID 放入广播数据中。

待确认：

- AES key 来源。
- AES key 是否全产品相同。
- AES key 是否需要按批次区分。
- 广播 UUID 是否固定不变。
- 是否需要定期变化以防止被长期跟踪。
- 手机上位机是否需要根据广播 UUID 反查真实唯一识别码。

## 9. BLE 广播与扫描需求

### 9.1 广播需求

设备在广播扫描状态和上位机连接状态下，应周期性广播本终端信息。

广播内容至少包括：

- 产品标识。
- 协议版本。
- 加密派生 UUID。
- 设备状态。
- 电池状态。
- 充电状态。
- 消息类型。
- 消息序号。
- 校验字段。

广播参数待确认：

- 广播类型：legacy advertising 或 extended advertising。
- 广播间隔。
- 广播信道。
- 广播功率。
- 广播数据最大长度。
- 是否使用 scan response。
- 手机是否通过广播识别设备，还是仅通过 GATT 连接后识别。

### 9.2 扫描需求

设备在广播扫描状态和上位机连接状态下，应扫描其他终端广播。

扫描处理需要：

- 过滤非本产品广播。
- 解析协议版本。
- 提取对端广播 UUID。
- 读取 RSSI。
- 更新附近终端状态表。
- 处理设备间广播消息。

扫描参数待确认：

- 扫描类型：主动扫描或被动扫描。
- 扫描间隔。
- 扫描窗口。
- 是否启用重复过滤。
- 连接状态下扫描占空比。

## 10. 设备发现需求

### 10.1 发现状态

对于扫描到的每个合法终端，本机需要单独维护一个发现状态。

发现状态包括：

- 未记录。
- S1。
- S2。
- S3。

S1、S2、S3 表示从远到近或从弱到强的三个发现等级。

### 10.2 RSSI 阈值

建议定义三个 RSSI 阈值：

- T1：进入 S1 的阈值。
- T2：进入 S2 的阈值。
- T3：进入 S3 的阈值。

由于 RSSI 通常为负数且数值越大表示信号越强，建议满足：

- `T3 > T2 > T1`。

例如：

- T1 = -80 dBm。
- T2 = -65 dBm。
- T3 = -50 dBm。

待确认：

- 原需求中“RSSI 小于阈值”是否应修正为“RSSI 大于或等于阈值”。
- T1/T2/T3 默认值。
- 阈值是否允许手机上位机配置。

### 10.3 状态进入逻辑

当未记录设备的 RSSI 持续满足 `RSSI >= T1` 达到 Tin 后：

- 记录该终端状态为 S1。
- 驱动马达振动一次。
- 若手机已连接，则上报 S1 进入事件。

当 S1 设备的 RSSI 持续满足 `RSSI >= T2` 达到 Tin 后：

- 记录该终端状态为 S2。
- 驱动马达振动两次。
- 若手机已连接，则上报 S2 进入事件。

当 S2 设备的 RSSI 持续满足 `RSSI >= T3` 达到 Tin 后：

- 记录该终端状态为 S3。
- 驱动马达振动三次。
- 若手机已连接，则上报 S3 进入事件。

### 10.4 状态退出逻辑

当 S3 设备的 RSSI 持续满足 `RSSI < T3` 达到 Tout 后：

- 记录该终端状态为 S2。
- 驱动马达振动三次。
- 若手机已连接，则上报 S3 退出事件或 S2 回退事件。

当 S2 设备的 RSSI 持续满足 `RSSI < T2` 达到 Tout 后：

- 记录该终端状态为 S1。
- 驱动马达振动两次。
- 若手机已连接，则上报 S2 退出事件或 S1 回退事件。

当 S1 设备的 RSSI 持续满足 `RSSI < T1` 达到 Tout 后：

- 删除该终端记录。
- 驱动马达振动一次。
- 若手机已连接，则上报 S1 退出事件。

### 10.5 RSSI 滤波和防抖

为避免 RSSI 抖动导致频繁状态切换，发现算法应支持：

- Tin 进入确认时间。
- Tout 退出确认时间。
- RSSI 平滑滤波。
- 每个终端独立计时。
- 状态切换冷却时间。

待确认：

- RSSI 使用瞬时值、滑动平均值还是中位数。
- Tin 默认值。
- Tout 默认值。
- 状态切换后是否需要冷却时间。
- 多设备同时触发振动时如何排队。

### 10.6 附近终端状态表

设备需要维护附近终端状态表。

每条记录至少包含：

- 对端广播 UUID。
- 对端短地址或派生 ID。
- 当前发现状态。
- 最近 RSSI。
- RSSI 滤波值。
- 最近接收时间。
- 进入计时。
- 退出计时。
- 最近事件序号。

待确认：

- 最大记录数量。
- 记录满时淘汰策略。
- 多久未收到广播后删除记录。
- 是否需要将状态表持久化。

## 11. 马达振动反馈需求

设备需要通过线性马达向用户提示发现状态变化。

振动模式：

| 事件 | 振动模式 |
| --- | --- |
| 进入 S1 | 振动 1 次 |
| 进入 S2 | 振动 2 次 |
| 进入 S3 | 振动 3 次 |
| 退出 S3 回到 S2 | 振动 3 次 |
| 退出 S2 回到 S1 | 振动 2 次 |
| 退出 S1 并删除记录 | 振动 1 次 |

待确认：

- 单次振动时长。
- 多次振动间隔。
- 多个设备事件同时发生时的振动排队策略。
- 手机连接状态下是否允许关闭振动。
- 低电量状态下是否禁止振动。
- DRV2625 初始化和触发参数。

## 12. 设备间广播通信需求

### 12.1 通信目标

两个或多个产品之间需要通过 BLE 广播实现相互通信。

通信机制需要保证：

- 消息完整性。
- 消息去重。
- 分片重组。
- 超时处理。
- 收发完成后通知本机手机上位机。

### 12.2 消息类型

建议至少定义以下消息类型：

- 发现广播。
- 单包业务消息。
- 分片业务消息。
- 分片确认。
- 消息完成确认。
- 错误或拒绝消息。

### 12.3 消息字段

广播消息建议包含：

- 协议 magic。
- 协议版本。
- 消息类型。
- 源设备 UUID。
- 目标设备 UUID 或广播目标。
- 会话 ID。
- 消息 ID。
- 分片序号。
- 分片总数。
- Payload 长度。
- Payload 数据。
- CRC 或 MAC。

### 12.4 完整性策略

如果业务要求强完整性，应采用确认机制：

- 发送方将消息分片。
- 每个分片携带消息 ID 和分片序号。
- 接收方缓存分片。
- 接收方在收齐后校验完整消息。
- 接收方通过广播发送 ACK。
- 发送方在超时时重发未确认分片或整条消息。
- 达到最大重试次数后上报失败。

待确认：

- 广播通信是单播、组播还是广播。
- 是否要求对端必须 ACK。
- 最大消息长度。
- 最大分片数。
- 重试次数。
- 超时时间。
- 是否需要加密 payload。
- 是否需要认证消息来源。

## 13. 手机上位机 GATT 通信需求

当前固件 `app_att.c` 中的 GATT 服务仍偏向示例工程，包含温湿度服务。后续需要替换或新增产品专用 GATT 服务。

### 13.1 建议服务

建议定义一个产品主服务，包含以下特征：

| 特征 | 方向 | 用途 |
| --- | --- | --- |
| Device Info | Read | 读取设备版本、硬件版本、协议版本 |
| Device ID | Read | 读取本机唯一识别码派生信息 |
| Device State | Read/Notify | 读取和通知系统状态 |
| Battery State | Read/Notify | 读取和通知电池与充电状态 |
| Discovery Event | Notify | 上报附近设备发现事件 |
| Nearby Table | Read | 读取当前附近终端状态表 |
| Command | Write | 手机下发命令 |
| Command Result | Notify | 命令执行结果 |
| Peer Message TX | Write | 手机请求发送设备间消息 |
| Peer Message RX | Notify | 通知收到的设备间消息 |
| Config | Read/Write | 读取和设置参数 |
| Error State | Read/Notify | 读取和通知错误状态 |

### 13.2 手机命令

建议支持的手机命令：

- 获取设备状态。
- 获取附近设备列表。
- 清空附近设备列表。
- 发送设备间消息。
- 设置 RSSI 阈值。
- 设置 Tin/Tout。
- 设置休眠时间。
- 设置振动开关。
- 读取 Flash 配置。
- 恢复默认配置。
- 重启设备。

待确认：

- 手机是否需要绑定设备。
- 是否需要配对加密。
- 是否允许任意手机连接。
- 是否支持 OTA。

## 14. 电池与充电需求

### 14.1 电池电压检测

硬件电池检测电路采用分压网络。

分压比例：

- ADC 电压 = 78.4% 电池电压。

电池电压范围：

- 电池电压 2.7V 到 4.2V。
- 对应 ADC 输入约 2.12V 到 3.29V。

设备应周期性检测电池电压，并转换为电池状态。

待确认：

- ADC 参考电压和采样方式。
- 低电压告警阈值。
- 低电压关机阈值。
- 上报给手机的是电压值、电量百分比还是电池等级。

### 14.2 充电检测

新版硬件使用 PA0 检测充电状态。

高电平表示充电事件。

设备应检测：

- 充电开始。
- 充电结束。
- 当前是否处于充电中。

待确认：

- 充电开始是否立即休眠。
- 充电中是否允许 BLE 广播或手机连接。
- 充电结束后是否自动唤醒并进入广播扫描状态。
- 充电检测是否需要边沿中断。

## 15. Flash 数据需求

设备 Flash 中需要保存：

- 唯一识别码。
- 产品配置参数。
- BLE MAC 地址。
- 校准参数。
- 手机绑定信息。
- 设备间通信必要状态。
- 错误日志或重启原因。

配置参数建议包含：

- 数据版本。
- RSSI 阈值 T1/T2/T3。
- Tin。
- Tout。
- 休眠超时时间。
- 手机通信空闲超时时间。
- 振动开关。
- 广播间隔。
- 扫描参数。
- CRC。

待确认：

- Flash 分区地址。
- 与 SDK 现有 MAC、校准、pairing、OTA 区域是否冲突。
- 是否需要磨损均衡。
- 是否需要断电保护。

## 16. 安全需求

系统至少需要考虑：

- 唯一识别码不明文广播。
- 手机连接权限控制。
- 设备间消息来源认证。
- 广播消息防伪造。
- 广播消息防重放。
- 配置写入权限控制。

待确认：

- 是否启用 BLE SMP 配对。
- 是否要求手机登录账号后才能绑定设备。
- AES key 的生产和保护方式。
- 设备间消息是否需要加密。
- 广播 UUID 是否需要周期性滚动。

## 17. 调试与量产需求

### 17.1 调试需求

固件需要支持 UART 调试输出。

调试输出至少包含：

- 启动信息。
- 当前系统状态。
- BLE 连接和断开事件。
- 扫描到的合法设备信息。
- RSSI 状态变化。
- 广播消息收发结果。
- 休眠和唤醒原因。
- 错误码。

待确认：

- UART 引脚是否使用新版硬件定义。
- 量产固件是否关闭 UART 输出。

### 17.2 量产需求

量产流程需要支持：

- 烧录固件。
- 烧录唯一识别码。
- 写入 BLE MAC 或读取芯片已有 MAC。
- 写入 AES key 或 key 派生材料。
- 校验 Flash 数据。
- 测试 BLE 广播。
- 测试手机连接。
- 测试振动马达。
- 测试振动检测唤醒。
- 测试充电检测。
- 测试电池电压检测。

待确认：

- 是否需要专用生产测试固件。
- 唯一识别码生成系统。
- 生产测试结果是否需要写入 Flash。

## 18. 当前固件现状和差距

当前工程已有能力：

- BLE 初始化。
- 扩展广播初始化。
- 扫描初始化。
- 广播报告解析。
- RSSI 打印。
- 手机连接和断开事件回调。
- 简单连接状态记录。
- 250ms 周期任务。
- 简单深睡逻辑。
- 示例 GATT 表。

当前工程与需求的主要差距：

- 引脚定义未与硬件文档统一。
- 还没有产品级状态机。
- 还没有唯一识别码 Flash 存储和校验。
- 还没有 AES 派生广播 UUID。
- 还没有设备发现状态表。
- 还没有 RSSI 阈值、Tin/Tout 和滤波逻辑。
- 还没有马达驱动。
- 还没有充电检测。
- 还没有电池电压检测接入业务。
- 还没有设备间广播通信协议。
- 还没有产品专用 GATT 服务。
- 还没有完整错误状态处理。
- 还没有量产烧录和校验流程。

## 19. 待确认问题汇总

开发前建议优先确认以下问题：

1. 最终使用新版硬件还是旧版硬件。
2. 固件是否需要兼容多版硬件。
3. 振动检测最终引脚是 PC1 还是 PA0。
4. 充电检测最终引脚是否为 PA0。
5. UART 调试是否使用 PC2/PC3/PC0/PC4。
6. RSSI 阈值判断方向是否修正为 `RSSI >= 阈值`。
7. T1/T2/T3/Tin/Tout 默认值。
8. 手机连接时是否必须继续广播和扫描。
9. 充电开始后是否立即断开手机并休眠。
10. 充电中是否允许 BLE 工作。
11. 唯一识别码 Flash 地址。
12. AES key 来源和管理方式。
13. 广播 UUID 是否固定或滚动变化。
14. 设备间通信是否必须 ACK。
15. 设备间消息最大长度。
16. 手机上位机是否需要绑定和配对。
17. 是否支持 OTA。
18. 量产时是否需要专用测试固件。
