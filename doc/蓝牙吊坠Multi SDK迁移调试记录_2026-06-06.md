# 蓝牙吊坠 Multi SDK 迁移调试记录 2026-06-06

## 已完成

1. 在 `tc_ble_multi_sdk/vendor/pendant/` 下完成旧业务模块迁移。
2. 保留 Multi SDK 平台入口文件，并接入 `app_pendant_init()` / `app_pendant_poll()`。
3. 接入 UART 调试接口 `tc_ble_multi_sdk/application/uartinterface/`。
4. 修正 `u_printf`：改为直接使用 `uart_ndma_send_byte()` 输出，绕开 `UART_PRINT_DEBUG_ENABLE=0` 时 `putchar()` 不输出的问题。
5. 修正 UART 波特率：使用 `uart_init_baudrate(115200, CLOCK_SYS_CLOCK_HZ, ...)`，适配 Multi SDK 当前 32 MHz 系统时钟。
6. 修正扩展广播数据更新：`setExtAdvData()` 失败时自动重启吊坠扩展广播 handle 后重试。
7. 删除 `tc_ble_multi_sdk/vendor/pendant/legacy_single_sdk/` 临时搬运目录。
8. 更新 `tools/build_pendant_multi.ps1`，默认使用已验证的命令行 `make` 构建，保留 `-Headless` 作为 Telink IDE console 构建入口。

## 已验证

1. 命令行构建通过：
   - `powershell -ExecutionPolicy Bypass -File .\tools\build_pendant_multi.ps1`
   - 输出：`tc_ble_multi_sdk/build/B85/pendant/pendant.bin`
   - 当前 size：`text=119820, data=1136, bss=22804, total=143760`
2. BDT 命令行烧录通过：
   - `powershell -ExecutionPolicy Bypass -File .\tools\flash_pendant_multi.ps1`
3. 串口启动与 shell 正常：
   - `Pendant boot`
   - `[ADV-TX] len=5b`
   - `info` 返回 `state=2`、`short=120b0100`
   - `beacon` 返回 `st=0`
4. Windows/Bleak 可扫描到 legacy 广播：
   - name：`PENDANT`
   - address：`A4:C1:38:A9:9B:65`
5. GATT 调试服务可发现并可收发：
   - service：`01000056-4544-3159-4b45-000150544e44`
   - cmd/rsp/log/evt 特征均存在
   - `GET_DEVICE_INFO` 可返回完整响应分片。

## 当前遗留

1. Windows `pc_adv_probe` 暂未解析到吊坠扩展 Beacon，`scan 10` 结果为 0 个 Beacon EID。
2. legacy 广播和 GATT 已确认可用，因此当前不是固件完全不广播，而是扩展广播 PC 接收或 Multi SDK 扩展广播数据链路仍需专项验证。
3. 尚未完成两块 B85 之间的扩展广播互扫验证。
4. 因扩展广播互扫尚未最终确认，暂不删除旧 `tc_ble_single_sdk/`。

## 下一步建议

1. 用两块 B85 同刷 Multi SDK 固件，分别接串口，测试 `peers` 是否能发现对方。
2. 若两块 B85 可互扫，优先继续手机 GATT + B85 扩展广播互联方案。
3. 若两块 B85 仍无法互扫，继续检查 Multi SDK 扩展扫描事件数据状态和 secondary PHY/AUX 配置。
