# 微光 App 终端发现机制工作小结 2026-06-27

## 今日目标

使用 4 块 B85 微光终端和 1 台 Android 手机，验证正式 App 的“附近微光”发现机制：

- 1 块终端作为 App 绑定设备，保持 GATT 调试通道连接。
- 另外 3 块终端依次进入范围、退出范围。
- App 附近页应自动显示进入范围的用户卡片，并在终端离开后自动移除。

## 硬件与角色

- Android 手机：Pixel 9，通过 ADB 安装和抓取 UI。
- 绑定终端：COM16，资料为 `polaris / steady-light`，短 ID `6B463997`。
- 附近终端：
  - COM9：`dawn / brief-spark`
  - COM10：`lantern / wind-kept`
  - COM17：`moon / tide-reply`
- 串口继电器：COM18，用于切换 Telink 烧录器连接到不同 B85 板。

## 主要修改

### Android App

- 修复附近页计数逻辑：使用 `peer table` 与 `peer profile` 的 short ID 并集计算可见人数，避免资料卡未到时计数和列表不一致。
- 增加附近资料卡分页拉取：
  - App 发送 `GET_PEER_PROFILES(startIndex)`。
  - 下位机返回一页资料和 `nextIndex`。
  - App 按请求 seq 聚合多页结果，最后一页到齐后统一刷新 UI。
- 修复 `HostProtocol.parsePeerProfilePage()` 的 offset bug：
  - 之前解析完 signature 后没有跳过 `signatureLen`。
  - 导致把签名首字母当作 `nextIndex`，例如 `brief-spark` 的 `b=98`。
  - 修复后分页链路正确表现为 `next=1 -> next=2 -> -1`。
- GATT 命令写入改为 `WRITE_TYPE_NO_RESPONSE` 并增加发送 pacing，用于提高调试通道命令发送稳定性。

### B85 下位机

- 连接手机后降低扩展扫描占空比：
  - 未连接：较高扫描占空比，便于发现附近终端。
  - 已连接：低占空比扫描，避免抢占 GATT 连接事件导致 Android `status=8 / HCI_ERR_CONNECTION_TOUT`。
- 增加扫描周期性重启，降低长时间扫描卡住的概率。
- 开发 fallback 身份改为基于 Flash UID 生成并持久化，避免没有正式身份的开发板每次 reset 后 EID 改变。
- 附近资料卡缓存数量提升到 3，支持当前 1 个绑定终端观察 3 个附近终端。
- `GET_PEER_PROFILES` 支持分页返回，并过滤已经离开范围的 profile。

### 工具脚本

- 继电器脚本支持 4 块板的目标选择。
- 当前实测 COM9 在 BDT `ac` 后容易丢 EVK 句柄，刷写时使用 `-SkipActivate` 更稳定。

## 验证结果

### 四块终端刷写与串口

- 四块板均可通过串口 shell 访问。
- 四块板均已刷入 clean build 固件。
- COM9 使用 `-SkipActivate` 后刷写成功；其余板正常刷写。

### App 绑定与连接稳定性

- App 自动连接绑定终端 COM16。
- 连接状态保持稳定，测试过程中没有再出现 GATT 超时断开。

### 三终端同时出现

最终附近页显示：

- `dawn / brief-spark`
- `moon / tide-reply`
- `lantern / wind-kept`

计数显示为 `附近有 3 位微光`，列表中 3 张真实资料卡均正确显示。

### 逐个退出

按顺序执行：

1. COM9 `ble stop`，App 从 3 位变为 2 位，剩余 `moon` 和 `lantern`。
2. COM10 `ble stop`，App 从 2 位变为 1 位，剩余 `moon`。
3. COM17 `ble stop`，App 变为空列表，显示“附近暂时没有微光 / 暂无”。

结果符合预期。退出不是即时删除，而是等待 B85 peer table 超时后由 App 同步刷新。

## 已知问题

- `ble stop` 后再执行 `ble start`，部分板子 radio 状态显示已开启，但不能稳定重新进入互扫网络。当前用 `reset`/重新上电模拟“重新出现”是稳定的。后续需要单独修 BLE start 恢复路径。
- BDT 在部分状态下 `ac` 会让 EVK 句柄丢失，尤其是 COM9 当前链路；后续可以把继电器刷写脚本的默认策略调整为可配置或对特定目标跳过 active。

## 当前状态

- App 已安装最新调试版。
- COM16 为绑定终端并保持连接。
- COM9、COM10、COM17 在最后退出测试中已执行 `ble stop`，因此当前附近页应为空。
